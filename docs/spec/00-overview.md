# 00 项目概述

## 1. 一句话定义

面向跨境电商卖家的问答系统，回答 Amazon 平台规则与欧盟增值税（Value Added Tax, VAT）/ 进口一站式服务（Import One-Stop Shop, IOSS）合规问题，**所有回答必须附带可追溯的原文引用**。

## 2. 要解决的问题

跨境电商卖家在合规问题上处于三重困境：

1. **信息分散**：平台规则在 Seller Central，税务规则分散在欧盟官方站点与各国税务局，卖家需要跨多个来源自行拼凑
2. **专业门槛高**：VAT、IOSS、OSS、远程销售阈值等概念相互关联且互为前提，非财税背景的卖家难以理清
3. **时效性强**：平台政策与税率屡有修订，卖家检索到的信息可能是已失效的旧版本

通用大语言模型直接回答这类问题的核心风险是**幻觉（Hallucination）**：会编造出看似合理但实际不存在的条款编号、税率数字和生效日期，且无法提供出处。在合规场景下，一个编造的税率比一句「不知道」危害大得多——卖家可能据此做出错误的经营决策。

本项目的核心主张：

> 把回答锚定在可追溯的原文上；无法从语料中找到依据时，**明确声明依据不足，而不是给出推测**。

## 3. 目标用户

**跨境电商卖家**，特征如下：

| 维度 | 描述 |
|---|---|
| 业务形态 | 在 Amazon 欧盟站点销售，可能是自配送或使用亚马逊物流（Fulfillment by Amazon, FBA） |
| 规模 | 中小卖家，无专职财税团队 |
| 知识背景 | 有电商运营经验，但缺乏税务专业知识 |
| 核心诉求 | 快速得到「我的情况适用哪条规则」的判断依据，而不是完整的税法教材 |
| 典型使用时机 | 开拓新站点前评估合规成本、收到平台合规通知后确认应对、日常运营中遇到具体疑问 |

用户**不是**：专业税务顾问、会计师、法律从业者。系统不替代专业意见。

## 4. 用户故事

| 编号 | 用户故事 | 验收要点 |
|---|---|---|
| US-01 | 作为在 Amazon 欧盟站点销售的卖家，我想知道我的业务是否需要注册 VAT，以便判断是否要立即处理 | 回答必须引用具体判定条件及其适用国家；语料无法支撑时必须声明依据不足 |
| US-02 | 我想理解 IOSS 与 OSS 的区别及各自的适用条件，以便判断自己该走哪条申报路径 | 引用须指向官方定义原文，不得由模型自行归纳概念差异 |
| US-03 | 我想知道 Amazon 对卖家提供 VAT 税号的具体要求，以及未提供的后果 | 必须区分「平台要求」与「法律义务」；引用 Amazon 政策原文 |
| US-04 | 得到回答后，我想继续追问特定国家或特定货值区间的情况 | 追问保留上下文；若新问题超出语料覆盖，必须重新声明依据不足，不得沿用上一轮结论 |
| US-05 | 我想限定只检索某个国家或某类文档，以便排除无关内容 | 筛选条件必须作用于**检索层**，而非仅做展示层过滤 |
| US-06 | 我想知道某条规则的生效时间和文档采集时间，以便判断信息是否仍然有效 | 每条引用必须展示文档生效日期与采集日期 |
| US-07 | 我想点开引用看到原文片段和出处链接，以便自行核实 | 引用包含文档标题、段落定位、原文片段、来源链接 |
| US-08 | 当系统无法回答时，我希望它明确说不知道，而不是给我一个看起来合理的答案 | 存在「依据不足」的显式响应路径，且该路径可被评测识别 |

## 5. 能力概览

系统对外提供四类能力：

1. **检索问答**：多轮对话形式，基于检索到的原文片段生成回答，回答中每个结论都挂载引用标记
2. **引用溯源**：每条引用可展开查看原文片段、文档标题、生效日期、采集日期与来源链接
3. **维度筛选**：按国家、文档类型、发布机构等维度限定检索范围
4. **依据不足声明**：当检索结果的相似度低于阈值，或模型判断语料无法支撑回答时，走显式拒答路径

## 6. 系统边界

系统**不做**什么，见 `01-scope.md`。该文档是防止范围膨胀的强制约束，与本文件冲突时以 `01-scope.md` 为准。

## 8. 成功判据

项目成效由三个可量化的判据衡量，具体指标与基线在 `05-acceptance.md` 中定义：

1. **准确性**：回答中的事实性陈述能在引用原文中找到支撑的比例
2. **可溯源性**：回答中带引用的陈述占比，以及引用是否真的指向支撑该陈述的片段
3. **拒答可靠性**：对语料覆盖范围外的问题，系统正确拒答的比例
