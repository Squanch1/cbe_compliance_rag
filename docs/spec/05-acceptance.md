# 05 验收标准与指标

## 0. 本文档的作用

`00-overview.md` 第 8 节定了三个成效判据——准确性、可溯源性、拒答可靠性——具体指标与基线在本文件定义。`01-scope.md` 第 3 节灰色地带的处理原则，验收方式也在本文件落地。

与 `01-scope.md` 冲突时以它为准：那份文档是强制边界约束，本文件只负责把边界内的东西变成可度量的。

---

## 1. 判定方式

### 1.1 判定数据来自评测集

评测集是 `data/eval_cases.csv`，由 `src/cbe_rag/evaluation/cases.py` 读取校验，跑法与报告见 `scripts/calibrate_threshold.py`。

> **与 `03-data-model.md` 第 3.5 节的差异**：那一节定义了 `eval_cases` 表，实现用的是 CSV。CSV 便于人工改、能进版本控制、能看到改动历史，与 `manifest.csv` 同一套做法。表建着但没在用，**这个不一致要处理**——要么把 CSV 灌进表，要么改那一节的表述。
>
> 评测结果本身**不落库**（`03-data-model.md` 第 3.5 节：首期评测以脚本输出报告的形式进行）。

### 1.2 三种结局

一次问答有三种结局，指标要分开看，不能混：

| 结局 | 触发 | 有没有调模型 |
|---|---|---|
| 程序拒答 `refused = true` | 检索结果的稠密余弦低于粗筛线 | 没有 |
| 模型降级 `degraded = true` | 调了模型，但回答里一条合法引用都没有，已替换成「依据不足」 | 调了 |
| 正常回答 | 其余 | 调了 |

定义见 `04-api-contract.md` 第 2.2 节。

**「系统没有给出无依据的答案」不等于 `refused = true`**——模型自己说「依据不足」并触发 `degraded` 同样算数。这个区别在改粗筛语义时定的（见 `02-architecture.md` 6.3）。

## 2. 指标

### 2.1 准确性：数字可溯率

**指标**：回答里出现的数字（金额、税率、天数、阈值、条款号），能在**同一条回答的引用原文**里找到的比例。

**为什么用数字而不是「整句对不对」**：合规场景下最有害的幻觉是编造的税率与金额（`00-overview.md` 第 2 节），而这类内容恰好可以用程序核对。「这句话意思对不对」判不了，硬判只会得到一堆不可复现的人工结论。

**度量**：脚本从回答里抽出数字，在每个被引用的子块原文里找。

**已知局限**：字面匹配会漏掉表述差异（`150 欧元` 与 `EUR 150`），需要做归一化。**宁可漏报不可误报**——误报会让这条指标失去可信度，进而被忽视，比不做还糟。

**状态**：未实现。

### 2.2 可溯源性

拆成三个子指标，因为它们的可靠程度差很多。

| 子指标 | 定义 | 度量的可靠性 |
|---|---|---|
| 引用覆盖率 | 带 `[n]` 标记的句子数 / 事实性句子数 | 中。分母「事实性句子」的切分本身有歧义 |
| 引用有效率 | 能解析到材料范围的编号数 / 全部编号数 | 高。纯程序判定，`check_citations` 的 `invalid_numbers` 为空即为通过 |
| 引用恰当率 | 引用是否真的支撑它挂的那句话 | **低，程序判不了** |

**引用恰当率只能人工抽样。** `generation/citations.py` 的模块注释把边界写得很清楚：程序能拦住引用了不存在编号的回答，但**不能**判断引用是否恰当——模型完全可能把 `[2]` 挂在只由 `[1]` 支持的结论上。那一层的可靠性靠评测集衡量。

**状态**：引用有效率已由 `check_citations` 实现；覆盖率与恰当率未实现。

### 2.3 拒答可靠性

**指标**：语料覆盖范围外的问题，系统没有给出无依据答案的比例。

**度量**：在评测集上按 `category` 分组统计，这是分类取值存在的理由（`03-data-model.md` 第 3.5 节：让拒答能力可被度量）。

| 分类 | 期望 | 验收看什么 |
|---|---|---|
| `out_of_scope` | 不给出实质回答 | 走了拒答（程序或模型任一条路径） |
| `calculation` | **引导式拒答** | 不只是拒答，还要说明缺哪些输入并引用计算方式的条款（`01-scope.md` 3.2） |

**只统计「答对了多少」会鼓励系统勉强作答**，把「该拒答时拒答」纳入评测才能约束住。

**状态**：标定脚本已能跑出分数分布；按分类统计拒答结局的部分未实现。

### 2.4 误伤率

**指标**：该答的问题被程序拒答的比例。

**为什么单列**：两边的代价不对称（`retrieval/service.py` 的 `passes_prefilter` 注释）：

- 漏拦的代价：多调一次模型，花点钱
- 误伤的代价：用户拿不到本来能答的问题

所以粗筛线的标定约束是**硬约束 `max_missed = 0`**，不是「误伤率尽量低」。`suggest_thresholds(scores, max_missed=0)` 就是按这个来的。

**状态**：已实现（`scripts/calibrate_threshold.py`）。

## 3. 评测集

### 3.1 当前规模

**26 条**，六类齐全：

| 分类 | 条数 | 期望行为 |
|---|---|---|
| `factual` | 12 | answer |
| `comparison` | 2 | answer |
| `advice` | 2 | answer |
| `calculation` | 2 | refuse |
| `out_of_scope` | 8 | refuse |
| `conflict` | 0 | 首期语料无支撑，见 `03-data-model.md` 第 3.5 节 |

该答 16、该拒答 10。

**`conflict` 一栏是 0。** 两道原本定为此类的题在 2026-09-30 的复核中被降为 `factual`——查证下来两版指南的差异是「新增」不是「矛盾」。不放用例，也不编一个假的凑数。

**两条硬约束**：

1. **refuse 类不能少。** 只有该答的题标不出阈值下界（`evaluation/cases.py` 的模块注释）。
2. **两类各自要有足够的样本量**，否则算出的「余量」不可靠——现在的 16 条该答就已经偏少。

### 3.2 出题的禁区

**期望行为必须人工判定**，判据是「语料里到底有没有能回答这个问题的内容」。

**绝不能先跑一遍看分数、再回头把分低的标成 refuse。** 那是用分数定义类别，再拿类别去标定阈值，绕一圈等于什么也没定。

### 3.3 已知局限

**出题人会偏向「语料里写得很清楚的地方」。** 看着语料编题，编出来的是「哪里写得好」，不是「用户会怎么问」。后者只有业务方知道，需要人工补题。

**26 条样本很少。** 据此算出的余量只能当参考，不能当结论。

## 4. 灰色地带的专项验收

对应 `01-scope.md` 第 3 节。这几条不是「尽量做到」，是明确的处理原则，逐条给验收方式。

| 场景 | 条款 | 期望行为 | 验收要点 |
|---|---|---|---|
| 概念比较类 | 3.1 | answer | 每条差异都要挂引用；且必须出现「以下对比由系统基于原文汇总，原文未直接进行此项对比」这类标注 |
| 计算类提问 | 3.2 | 引导式拒答 | 说明计算缺哪些输入，并引用原文中说明计算方式的条款 |
| 超出语料范围 | 3.3 | 拒答 | 明确声明语料未覆盖该主题；**不得用相近主题替代** |
| 多份文档冲突 | 3.4 | answer | **显式标注存在冲突与各自出处，不得静默选一份** |
| 结论性提问 | 3.5 | answer | 只给原文依据，**不得出现「你应该」「建议你」这类指令性表述** |

其中 3.1 和 3.5 的验收可以用程序做文本检查（关键词存在性判断），3.3 和 3.4 需要人工抽样——「是不是静默选了一份」程序看不出来。

**「多份文档冲突」这一行目前没有对应验收用例。** 经复核，两版欧盟指南之间不存在「同一件事各说各的」的情形，语料覆盖不到这个场景（查证过程见 `03-data-model.md` 第 3.5 节）。要么等语料扩充后再启用，要么按 `01-scope.md` 第 4 节的变更流程把它从首期范围里去掉——**在此之前不能算已验收**。

**全部待定。** 拒答阈值尚未标定（粗筛线还挂着一个未经标定的值），而 2.3 与 2.4 的基线直接取决于它。

| 指标 | 基线 | 状态 |
|---|---|---|
| 数字可溯率 | 待填 | 指标未实现，无法测量 |
| 引用覆盖率 | 待填 | 指标未实现，无法测量 |
| 引用有效率 | 待填 | 可测量（`check_citations` 已实现），尚未纳入评测脚本 |
| 引用恰当率 | 待填 | 只能人工抽样，抽样方案未定 |
| 拒答可靠性（按分类） | 待填 | 待拒答阈值标定后回填 |
| 误伤率 | 待填 | 待拒答阈值标定后回填 |

**基线定下来之前，这些指标只能看趋势，不能当验收依据。** 填基线的前提是：

1. 粗筛线标定完成
2. 数字可溯率与引用覆盖率的度量脚本实现
3. 评测集样本补到足以支撑结论的规模
